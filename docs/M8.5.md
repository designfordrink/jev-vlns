# M8.5 — Oracle / Candidate Landscape

## Research question

The current Container Stack neighborhood is deliberately small. Before connecting a real JEV model, determine whether the neighborhood already contains substantially better candidates than Random or the deterministic selector can find.

## Oracle

The Oracle enumerates all legal repair plans for a selected destroy neighborhood and uses the same projected_objective() as the solver to score them. For destroy selection it scores each destroy candidate by the best repair plan available after that destroy.

This is an experimental upper-bound control, not a production solver.

## Metrics

- **Destroy regret** = selected destroy potential − best destroy potential.
- **Repair regret** = selected complete repair score − best repair score for the selected destroy.
- Candidate counts for destroy and repair stages.
- Final moves remains the primary solver outcome.

## Controlled modes

- random-random
- oracle-random
- random-oracle
- oracle-oracle

The existing Fake JEV and heuristic System-1 surrogate controls remain separate. They must not be interpreted as evidence about real JEV quality.

## Interpretation

If Oracle substantially outperforms Random, the current neighborhood contains useful choices and selector quality becomes the next research target.

If Oracle is close to Random, improving the neighborhood generator becomes the more direct next experiment.

Only after this landscape is understood should the real JEV API be introduced into the benchmark.
