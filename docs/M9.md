# M9 — Real JEV as Destroy Selector

## Hypothesis

Keep Repair deterministic/random and replace only the Destroy selector with the real
JEV API.

The controlled comparison is:

| Destroy | Repair |
|---|---|
| Random | Random |
| Oracle | Random |
| **Real JEV** | Random |

All three use the same seeded initial state, neighborhood generator, objective,
acceptance rule and iteration budget.

## What JEV sees

JEV receives the complete serialized Container Stack state plus a finite set of
legal Destroy candidates. It returns the ID of one candidate.

JEV does not mutate state, execute a destroy, or validate legality.

## Current TypeSafe protocol

The client sends a Choice question to POST /v1/systemone and normalizes the
response from answers.choice.choice and answers.choice.confidence.

The API contract is verified by a unit test using a recorded response shape.

## Metrics

In addition to final moves:

- Destroy regret against the exact Oracle;
- number of JEV calls;
- JEV fallback count;
- accepted JEV decisions;
- average latency;
- input/output token counts;
- confidence threshold.

## Live command

Set a JEV-compatible API key in the environment, then run:

    python experiments/run_real_jev_destroy.py --seeds 1 2 3 4 5 --iterations 50

The command fails explicitly if no API key is configured. It never silently turns a
missing JEV key into a baseline run.

## Important methodological rule

Do not conclude that JEV improves the solver from one run. The first useful result
is a fixed-seed comparison against Random and Oracle. The main question is whether
real JEV's destroy choices have lower regret than Random and approach the Oracle
landscape.
