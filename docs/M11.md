# M11 — JEV Choice vs Local Landscape

## Research question

M9/M10 showed the outcome of VLNS runs and allowed inspection of individual decisions. M11 asks a narrower question:

> When JEV selects a Destroy candidate, how good is that discrete choice relative to the other legal candidates available at the same state?

This separates **choice quality** from **solver quality**.

## Metrics

For every Destroy decision:

- **Top-1 rate** — fraction of decisions where the selected candidate has the best downstream Oracle score.
- **Mean rank** — rank of the selected candidate after sorting candidates by downstream score; 1 is best.
- **Mean regret** — selected score minus the best score.
- **Normalized regret** — regret divided by the score range in that iteration; 0 is best, 1 is worst.

Ties receive the best rank.

## Reproducible multi-seed experiment

The repository now provides one command that generates all M11 replays and the aggregate report:

~~~bash
python experiments/run_choice_quality.py \\
  --seeds 1 2 3 4 5 \\
  --iterations 50 \\
  --output experiments/runs/m11-choice-quality
~~~

It writes:

- experiments/runs/m11-choice-quality.json — protocol, per-run metrics and aggregate summary.
- experiments/runs/m11-choice-quality.md — human-readable report.

The default matrix contains:

- random-random — baseline;
- heuristic-random — offline HeuristicJEV surrogate;
- oracle-random — local-choice upper control.

All modes use the same seeds and iteration budget.

## Single-run analysis

Individual replays can still be generated and compared manually:

~~~bash
python experiments/run_replay.py --mode random-random --seed 42 --iterations 25 --output experiments/runs/random-42
python experiments/run_replay.py --mode heuristic-random --seed 42 --iterations 25 --output experiments/runs/heuristic-42
python experiments/run_replay.py --mode oracle-random --seed 42 --iterations 25 --output experiments/runs/oracle-42

python experiments/analyze_choice_quality.py \\
  experiments/runs/random-42.json \\
  experiments/runs/heuristic-42.json \\
  experiments/runs/oracle-42.json \\
  --output experiments/runs/m11-choice-quality.md
~~~

## Interpretation

The most important comparison is not simply final moves.

If a selector has a high Top-1 rate and low normalized regret but does not improve final moves, that means the local landscape is not sufficient to predict long-run solver quality.

If a selector has poor choice quality and poor final outcomes, M11 identifies a direct failure mode.

If JEV has better choice quality than a surrogate while final solver performance is unchanged, that is evidence that the selector is making better local decisions but that another part of VLNS is limiting end-to-end performance.

## Controls

- Random provides a chance-level baseline.
- Oracle provides the upper control for local choice quality.
- HeuristicJEV is an offline surrogate and must not be described as real JEV.
- Real JEV should be evaluated only with the same candidate sets, seeds, budgets and acceptance protocol.

## Methodological constraint

M11 does not change the solver. It only analyzes the M10 trace.

The Oracle scores are computed independently after candidate generation and are diagnostic evidence; they are never passed to JEV.

The batch experiment is deliberately offline and therefore suitable for CI. It does **not** require a live JEV API key.
