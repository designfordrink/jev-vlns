# M13 — Real JEV End-to-End Validation

## Research question

M12 asks whether real JEV makes good local Destroy choices. M13 asks the next question:

> Does real JEV Destroy choice quality translate into better final VLNS solutions?

The experiment compares real JEV Destroy + Random Repair against Random Destroy + Random Repair.

## Protocol

- paired seeds: 1, 2, 3, 4, 5 by default;
- 50 VLNS iterations per seed;
- identical initial state for each paired seed;
- identical Random Repair protocol;
- identical acceptance rule;
- only the Destroy selector changes;
- real JEV never receives Oracle scores or future outcomes.

The primary outcome is final moves; lower is better.

## Run

Configure one of:

- JEV_API_KEY
- TYPESAFE_API_KEY
- OPENROUTER_API_KEY

For OpenRouter:

    OPENROUTER_API_KEY=...
    TYPESAFE_BASE_URL=https://openrouter.ai/api
    JEV_MODEL=typesafe/jev-1.13

Then:

    python experiments/run_m13_real_jev_end_to_end.py \
      --seeds 1 2 3 4 5 \
      --iterations 50 \
      --output experiments/runs/m13-real-jev-end-to-end

The command writes:

- m13-real-jev-end-to-end.json
- m13-real-jev-end-to-end.md

## Primary metrics

For every paired seed:

- Random final moves;
- Real JEV final moves;
- paired delta = JEV − Random;
- whether JEV wins the seed.

Aggregate:

- mean final moves for both selectors;
- mean and median paired delta;
- JEV win rate;
- fallback count;
- JEV calls;
- total API cost.

Negative delta means JEV is better for that seed.

## Interpretation

A positive result is evidence that the selector boundary matters end-to-end: better Destroy decisions can improve the final search result without changing Repair.

A negative result is also useful. If M12 choice quality is good but M13 final outcomes do not improve, the bottleneck is likely downstream: repair, acceptance, trajectory effects, or mismatch between local Oracle quality and long-horizon search value.

Do not interpret five seeds as proof of general superiority. This remains a controlled research prototype.

## Relationship to M12

M12 measures local choice quality using downstream Oracle diagnostics.

M13 measures actual final search quality.

The two experiments should be reported together:

1. M12: did JEV choose locally good neighborhoods?
2. M13: did those choices improve the final solution?

Fallbacks must always be reported separately because a run containing many fallbacks is not equivalent to a fully JEV-driven run.
